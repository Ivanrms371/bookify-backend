# Shared location catalog

The authenticated `/api/locations/options` endpoint is independent of tenant membership so it works during onboarding and in General Settings. The old onboarding options route is a compatibility alias. The only supported countries are Uruguay (UY), Argentina (AR), Peru (PE), Chile (CL) and Paraguay (PY).

Country codes and timezone identifiers follow [IANA zone.tab](https://data.iana.org/time-zones/tzdb/zone.tab); currency defaults are UYU, ARS, PEN, CLP and PYG, these values cannot be overridden by the dashboard. Cities and street addresses are entered manually without geocoding. Canonical regions are validated per country, accepting case/accent variations.

Region sources: [Uruguay](https://www.gub.uy/politicas-y-gestion/puntos-atencion-ciudadania-departamento), [Argentina](https://www.argentina.gob.ar/pais/provincias), [Peru](https://www.gob.pe/institucion/pcm/campa%C3%B1as/4107-peru-informacion-territorial-), [Chile](https://www.bcn.cl/siit/siit/siit/nuestropais/regiones) and [Paraguay](https://correoparaguayo.gov.py/sitio/el-codigo-postal-es-importante-para-ubicar-las-direcciones/). Peru includes Callao; Paraguay includes Asunción.

Onboarding derives currency and timezone from country/region. Argentina defaults to Buenos Aires; Chile defaults to Santiago. Regional metadata overrides the default for a selected province/region. Valparaíso uses mainland Santiago as the automatic default; Easter Island cannot be distinguished from region alone. Aysén uses America/Punta_Arenas as a runtime-compatible UTC-3 mapping because the installed Node timezone database (2025a) does not recognize the newer America/Coyhaique identifier. This matches current/future appointment clocks, not historical conversions before the 2025 change. [Chile’s official time guidance](https://www.gob.cl/noticias/guia-cambio-hora-invierno-2025-regiones-pasos/) documents the permanent UTC-3 rule for Aysén and Magallanes.

Settings uses the same catalog and displays currency/timezone as read-only fields. The backend recalculates and persists them on onboarding location saves, confirmation and General Settings updates. Client-supplied currency/timezone values are ignored for backward compatibility. Changing country resets region/city and derives new defaults; changing region resets city and its derived timezone preview. Preference values are validated before persistence. Legacy Spanish country labels are canonicalized to codes. Confirmation persists the latest location-derived preferences without resetting other booking rules. Unsupported historical drafts without saved preferences still load with legacy Uruguay defaults so the owner can select a supported country; new location writes and confirmation reject unsupported countries.

When updating supported markets, change this catalog and the frontend location schema together, then run location, onboarding and Settings tests. Adding markets requires a product decision; the API deliberately does not expose a worldwide catalog.
